LESSON 2 - Injecting authentication into the ViewModel
====================================================================

Goal
----
Make `SimpleAndroidViewModel` depend on the abstraction `AuthRepository`, and
add a small function that can call `login`.

Why this layer exists
---------------------
The UI should not know how authentication works. The ViewModel receives user
actions from the UI, calls the repository, and later will expose the result as
UI state.

Task
----
Update `SimpleAndroidViewModel.kt`:

1. Add `AuthRepository` as a second constructor dependency.
2. Keep the existing `HomeRepository` dependency and greeting behavior.
3. Add a function named `login` with two `String` parameters: email and
   password.
4. Inside that function, call `authRepository.login(email, password)`.
5. Because the repository function is `suspend`, call it inside
   `viewModelScope.launch { ... }`.
6. For this lesson, store the returned Boolean in a private
   `MutableStateFlow<Boolean>` and expose it as a read-only `StateFlow<Boolean>`.
7. Start the Boolean state as `false`.

Clues
------

- Import `AuthRepository` from the `data.auth` package.
- Import `viewModelScope` from `androidx.lifecycle.viewModelScope`.
- Import `launch` from `kotlinx.coroutines.launch`.
- The constructor parameter should use the interface type, not
  `AuthRepositoryImpl`.
- The assignment inside the coroutine will look conceptually like:

      state = repository.login(email, password)

  but a `MutableStateFlow` is updated through its `.value` property.
